================================================================================

PROPÓSITO:
Sistema de facturación electrónica desktop para PyMEs chilenas. Integración
con SII (Servicio de Impuestos Internos) vía ChileAPI. Producto comercial
para venta, NO educativo.

OBJETIVO DE DESARROLLO:
3-4 semanas con IA vs 6+ meses manual. Prioridad: funcionalidad > perfección.

TECNOLOGÍAS PRINCIPALES:
- Electron 28.x (app desktop)
- React 18.x (UI)
- SQLite3 (base de datos local)
- Node.js/Express (servidor backend)
- PostgreSQL (base de datos servidor)

ARQUITECTURA:
Cliente (Electron) ←→ SQLite (local)
       ↕
Servidor (Railway) ←→ PostgreSQL
       ↕
ChileAPI ←→ SII (Gobierno)

3. ELECTRON: CONCEPTOS BÁSICOS
================================================================================

ELECTRON = Chromium + Node.js en un ejecutable desktop

PROCESOS:
1. Main Process (Node.js):
   - Corre en background
   - Acceso completo al sistema (archivos, DB, etc)
   - Crea ventanas (BrowserWindow)
   - Archivo: src/main/main.js

2. Renderer Process (Navegador):
   - Es tu UI (React)
   - Corre en cada ventana
   - NO tiene acceso directo al sistema (seguridad)
   - Archivo: src/renderer/src/main.jsx

3. Preload Script:
   - Bridge seguro entre main y renderer
   - Expone APIs específicas al renderer
   - Archivo: src/preload/preload.js

COMUNICACIÓN:
Renderer → Main: ipcRenderer.invoke('channel', data)
Main → Renderer: ipcMain.handle('channel', handler)

EJEMPLO FLUJO:
1. Usuario hace click "Guardar Cliente" (Renderer/React)
2. React llama: window.api.clientes.create(cliente)
3. Preload traduce: ipcRenderer.invoke('clientes:create', cliente)
4. Main recibe: ipcMain.handle('clientes:create', (event, cliente) => {...})
5. Main guarda en SQLite
6. Main retorna resultado
7. React actualiza UI

7. SQLITE: GUÍA RÁPIDA
================================================================================

CONEXIÓN:
---------
import Database from 'better-sqlite3';
const db = new Database('path/to/db.db');

QUERIES BÁSICAS:
----------------
// SELECT (múltiples)
const stmt = db.prepare('SELECT * FROM clientes WHERE id = ?');
const clientes = stmt.all(); // Array

// SELECT (uno)
const cliente = stmt.get(1); // Object o undefined

// INSERT
const stmt = db.prepare('INSERT INTO clientes (rut, nombre) VALUES (?, ?)');
const result = stmt.run('12345678-9', 'Empresa XYZ');
console.log(result.lastInsertRowid); // ID insertado

// UPDATE
const stmt = db.prepare('UPDATE clientes SET nombre = ? WHERE id = ?');
stmt.run('Nuevo Nombre', 1);

// DELETE
const stmt = db.prepare('DELETE FROM clientes WHERE id = ?');
stmt.run(1);

TRANSACCIONES:
--------------
const insert = db.prepare('INSERT INTO clientes (...) VALUES (...)');
const insertMany = db.transaction((clientes) => {
  for (const cliente of clientes) {
    insert.run(cliente);
  }
});
insertMany([cliente1, cliente2, cliente3]);

IMPORTANTE:
- better-sqlite3 es SÍNCRONO (no usa async/await)
- Siempre usa prepared statements (?) para prevenir SQL injection
- db.pragma('foreign_keys = ON') para integridad referencial

function importarExcel(filePath) {

async function enviarSII(factura) {
  const xmlContent = fs.readFileSync(factura.xml_path, 'utf8');

  const response = await fetch('https://api.chileapi.dev/v1/dte/enviar', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${CHILEAPI_KEY}`
    },
    body: JSON.stringify({
      rut_emisor: EMISOR_RUT,
      xml: xmlContent,
      idempotency_key: factura.idempotency_key
    })
  });

  const result = await response.json();

  if (result.success) {
    return {
      folio: result.folio,
      trackId: result.track_id,
      pdfUrl: result.pdf_url
    };
  } else {
    throw new Error(result.error);
  }
}

13. SISTEMA DE LICENCIAS
================================================================================

FLUJO:
1. Usuario instala app
2. App verifica licencia local
3. Si no existe, muestra ventana activación
4. Usuario ingresa license key
5. App valida con servidor
6. Servidor registra machine ID
7. App guarda license key local si válida

GENERAR LICENSE KEY (servidor):
--------------------------------
import { v4 as uuidv4 } from 'uuid';

function generarLicencia(clienteNombre) {
  const licenseKey = uuidv4();
  const expiresAt = new Date();
  expiresAt.setDate(expiresAt.getDate() + 365); // 1 año

  // Guardar en PostgreSQL
  await pool.query(
    'INSERT INTO licenses (license_key, client_name, expires_at) VALUES ($1, $2, $3)',
    [licenseKey, clienteNombre, expiresAt]
  );

  return licenseKey;
}

VALIDAR LICENCIA (cliente):
----------------------------
async function validarLicencia(licenseKey) {
  const machineId = getMachineId(); // os.hostname() + os.platform()

  const response = await fetch('https://tu-servidor.railway.app/api/licenses/validate', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ license_key: licenseKey, machine_id: machineId })
  });

  const result = await response.json();

  if (result.valid) {
    // Guardar local
    localStorage.setItem('license_key', licenseKey);
    return true;
  }

  return false;
}
